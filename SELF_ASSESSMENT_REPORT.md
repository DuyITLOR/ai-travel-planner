## What we did not manage

- The endpoint stores plans in memory (`InMemoryPlanStore`). The Postgres store, in one transaction,
  and the endpoints that create and edit plans come in PA#3; until then the deployed api has no plans
  to save.
- The validator enforces only the money rules (`over-member-cap`, `over-trip-budget`). Opening hours,
  travel time and rain need the shared place data (published 27 Nov) and are added in PA#3 as new
  rule codes.
- Token check uses the Supabase legacy HS256 JWT secret; asymmetric keys (JWKS) are not supported yet.
- PR #3's red commit was staged on purpose from a bug found the day before (see `PA2.md`,
  "Timeline"); we have no red PR that happened by accident.
